
# Data Dictionary

## 1. Purpose

This document defines the principal variables used in the econometric, machine-learning and forecast-evaluation stages of the project.

The two primary processed modelling datasets are:

- `data/processed/econometric_model_data.csv`
- `data/processed/ml_model_data.csv`

These datasets are generated by the notebook pipeline and are excluded from Git version control.

## 2. Observation Unit

The primary observation unit is a **food subclass in a specific month**.

The unique observation key is:

```text
Date + SubclassDescription
```

For forecast files containing multiple models, the unique key is:

```text
Date + SubclassDescription + Model + Representation
```

## 3. Core Identifier Variables

| Variable | Type | Description | Role |
|---|---|---|---|
| `Date` | Datetime | First calendar day representing the observation month | Time index |
| `GroupDescription` | Text | Broad CPI product-group description | Descriptive metadata |
| `ClassDescription` | Text | Food-class description associated with the subclass | Descriptive metadata |
| `SubclassDescription` | Text | Detailed food-price subclass name | Panel identifier and categorical ML feature |
| `Subclass_Weight` | Numeric | CPI aggregation weight assigned to the food subclass | Descriptive metadata |

`SubclassDescription` identifies the 46 food subclasses used throughout the final analysis.

`ClassDescription`, `GroupDescription` and `Subclass_Weight` are retained for interpretation and reporting but are excluded from the final machine-learning feature matrices.

| `ExchangeRate_Negative_Cumulative_Pct` | Numeric | Cumulative percentage | Cumulative sum of appreciation shocks |

### 4.2 Food-price inflation

Food-price inflation is defined as the monthly log change in the food-subclass CPI:

\[
FoodInflation_t =
100\left[\log(CPI_t)-\log(CPI_{t-1})\right]
\]

The variable is stored as:

```text
Food_Inflation_Pct
```

Positive values indicate monthly price increases, while negative values indicate monthly price decreases.

### 4.3 Exchange-rate change

The monthly exchange-rate change is calculated as:

\[
ExchangeRateChange_t =
100\left[\log(ER_t)-\log(ER_{t-1})\right]
\]

where \(ER_t\) is the USD/ZAR exchange rate.

The variable is stored as:

```text
ExchangeRate_Log_Change_Pct
```

The sign convention is:

- positive change: rand depreciation;
- negative change: rand appreciation;
- zero: no monthly log change.

### 4.4 Depreciation shock

The depreciation component is:

\[
Depreciation_t = \max(ExchangeRateChange_t,0)
\]

It is stored as:

```text
Depreciation_Shock_Pct
```

Validation constraint:

```text
Depreciation_Shock_Pct >= 0
```

### 4.5 Appreciation shock

The signed appreciation component is:

\[
Appreciation_t = \min(ExchangeRateChange_t,0)
\]

It is stored as:

```text
Appreciation_Shock_Pct
```

Validation constraint:

```text
Appreciation_Shock_Pct <= 0
```

### 4.6 Shock-decomposition identity

The positive and negative shock components exactly reconstruct the original exchange-rate change:

\[
ExchangeRateChange_t =
Depreciation_t + Appreciation_t
\]

The final validation produced a maximum shock-decomposition error of zero.

### 4.7 Cumulative exchange-rate components

The NARDL long-run variables are defined as:

\[
ER_t^{+}=\sum_{j=1}^{t}Depreciation_j
\]

\[
ER_t^{-}=\sum_{j=1}^{t}Appreciation_j
\]

They are stored as:

```text
ExchangeRate_Positive_Cumulative_Pct
ExchangeRate_Negative_Cumulative_Pct
```

The positive cumulative component is non-decreasing, while the signed negative cumulative component is non-increasing.

## 6. Target Variable

The machine-learning target is:

```text
Food_Inflation_Pct
```

This variable is excluded from all feature matrices for the corresponding current period.

The target is used only:

- when fitting models on the development data;
- when calculating validation metrics; and
- when evaluating the locked test predictions.

## 9. Appreciation Sign Convention Across Datasets

The econometric and machine-learning datasets use related but different appreciation conventions.

### Econometric convention

```text
Appreciation_Shock_Pct <= 0
```

The econometric component preserves the signed negative appreciation movement for NARDL partial-sum construction and coefficient interpretation.

### Machine-learning convention

```text
Appreciation_Magnitude_Lag*_Pct >= 0
```

The machine-learning component converts appreciation shocks to positive magnitudes:

\[
AppreciationMagnitude_t = |Appreciation_t|
\]

This allows the model to compare the magnitude of depreciation and appreciation movements using non-negative feature values.

The different conventions must be considered when interpreting estimated coefficients, feature effects and long-run multipliers.

## 10. Seasonal Variables

The monthly seasonal transformations are:

\[
MonthSin_t =
\sin\left(\frac{2\pi Month_t}{12}\right)
\]

\[
MonthCos_t =
\cos\left(\frac{2\pi Month_t}{12}\right)
\]

The pair represents annual seasonality without treating December and January as unrelated endpoints.

## 11. Split Variable

The `Split` column identifies the chronological modelling sample.

| Value | Period | Purpose |
|---|---|---|
| `Train` | October 2017–December 2023 | Initial model fitting |
| `Validation` | January 2024–December 2024 | Hyperparameter and representation selection |
| `Test` | January 2025–December 2025 | Locked final evaluation |

The split is chronological rather than random to preserve the time ordering of the data.

```text

```

It contains six columns.

| Variable | Type | Description |
|---|---|---|
| `Date` | Datetime | Forecast month |

## 13. Forecast-Evaluation Fields

The evaluated forecast file is:

```text
reports/tables/model_evaluation/combined_forecast_evaluation.csv
```

It contains the six prediction fields plus:

| Variable | Type | Description |
|---|---|---|
| `Actual` | Numeric | Observed monthly food-price inflation for the matching test record |

Forecast errors and performance measures are calculated from:

\[
Error_i = Prediction_i - Actual_i
\]

The target was absent from the original prediction file and was merged only during the final evaluation stage.

## 15. Performance-Measure Fields

Common performance-output variables include:

| Variable | Description |
|---|---|
| `Observations` | Number of forecast observations included |
| `MAE` | Mean absolute forecast error |
| `RMSE` | Root mean squared forecast error |
| `R2` | Coefficient of determination |
| `Directional_Accuracy_Pct` | Percentage of forecasts with the correct direction |
| `Mean_Bias` | Average prediction-minus-actual error |
| `RMSE_Improvement_vs_Persistence_Pct` | Percentage RMSE improvement relative to persistence |
| `MAE_Improvement_vs_Persistence_Pct` | Percentage MAE improvement relative to persistence |
| `RMSE_Rank` | Model rank ordered by RMSE |
| `MAE_Rank` | Model rank ordered by MAE |
| `Directional_Rank` | Model rank ordered by directional accuracy |

Lower MAE and RMSE values indicate better forecast accuracy.

Higher R² and directional-accuracy values indicate better performance.

A mean bias closer to zero indicates lower systematic overprediction or underprediction.

Non-finite predictions = 0
